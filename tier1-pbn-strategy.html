// CORE PRINCIPLE
為什麼 Tier-1 PBN 需要「同主題不同實作」
最常見的 PBN 失敗模式：
  • 把 ys89.fun 的 WordPress theme 複製到 PBN → footprint 立刻露餡
  • 內容直接抄 ys89.fun 的文章 → Google 識別 duplicate content
  • 用同樣的字體 + 同樣的配色 + 同樣的 logo 風格 → 視覺指紋
  • 同 hosting + 同 GA + 同 WHOIS → 帳號層級關聯
中任何一條都會讓主站 ys89.fun 連帶被 deindex 或降權。
Tier-1 PBN 正確思路：

買 Tier-1 域名是為了「假裝是獨立第三方 expert 在引用 ys89.fun」。所以技術上必須看起來跟 ys89.fun 完全沒關係，但主題上要跟 ys89.fun 同一個關鍵字池（這樣連結才有 SEO 價值）。

同主題 + 不同實作 + 不同寫作角度 = 看起來是 3 個獨立 expert 站。

⚙️ Hugo vs Astro 怎麼選？
  • Hugo（站 A 用）：Go 生態、build 極快、適合內容類站點，CSS 寫純粹的
  • Astro（站 B 用）：JS 生態、可加互動 widget（如百家樂模擬器），適合「需要 chart / calculator」的站
  • 為什麼不用同一個：兩站用相同 CMS = footprint 訊號，Google 偵測到後關聯雙站

// 雙站 footprint avoidance
Tier-1 專屬避雷清單（16 條紅線）
#紅線怎麼避
1同 IP / 同 C-class 主機站 A 用 CF Pages 帳號 1、站 B 用 CF Pages 帳號 2、ys89.fun 用 Cloudways
2同 WHOIS 註冊人啟用 WHOIS Privacy（CF Registrar / Namecheap 免費）
3同 Google Analytics IDTier-1 站建議不裝 GA，或站 B 用 Plausible 開源替代
4同 Google Search Console 帳號3 個 properties 用 3 個不同 Google 帳號驗證
5同 CMS / themeys89.fun: WordPress / 站 A: Hugo / 站 B: Astro（全部不同）
6同 footer 簽名每站獨立品牌名、聯絡方式
7同時上線時間站 A → 域名買到 5 天後上線，站 B → 站 A 上線後 7 天才上線
8同 anchor text 集中60/20/10/10 分配，每站獨立 anchor 庫
9每篇文章都連 ys89.fun10 篇文章只 3 篇連母站，其他自然
10內容跟原域名歷史毫無關係看買到域名的 Wayback 歷史，內容做「主題傳承」
11共用 CMS admin 帳號每站獨立 admin email
12共用社群帳號每站獨立 placeholder 社群（不一定要活躍）
13同樣的 OG image 風格 / favicon站 A 用米色實拍風 / 站 B 用學術圖表風
14同樣的 HTML structure（meta tags 順序）Hugo + Astro 預設輸出順序就不同 = 自然分散
15同樣的 robots.txt 寫法每站用 default（CMS 預設）即可
16同樣的 sitemap 命名（sitemap_index.xml）Hugo / Astro 預設都不一樣

⚠️ 絕對不要：
  • 站 A 跟站 B 同一天上線（時間 footprint）
  • 2 站同時連大量 ys89.fun（連結 burst）
  • 同一週 push 大量內容到兩站（內容 burst）
慢就是快。
