AI 自動發文 Pipeline 技術架構

2026-05-27 · ys89.fun 每日 5 篇自動化 · Claude API + WP-CLI · 5 編輯人設輪流

🎯 目標：每天自動產出 5 篇 SEO 文章，套用 5 個編輯人設（mark / 扁扁 / 阿奇 / 面具男 / 電玩凱凱）輪流發佈，內容品質要像真人寫，每月 150 篇，3 個月增加 450 篇。

🗺️ 整體 Pipeline 流程

1關鍵字佇列（Keyword Queue）

從 sites.json + Ubersuggest API 抓長尾關鍵字 → 寫入 backlog DB → 標記主題分類

2競品研究（SERP Analysis）

對每個關鍵字抓 Google 前 10 名 → 提取共同元素（標題模式、字數、結構）→ 餵給 AI 當參考

3內容生成（Content Generation）

Claude API (Sonnet 4.6) 寫文 → 套編輯人設 → 自動內嵌 wc-article 結構 + Schema + 內鏈

4品質檢查（QA）

字數檢查 / 關鍵字密度 / 敏感詞過濾 / 重複度檢查 / 內鏈數驗證

5排程發佈（Schedule）

WP-CLI 建草稿 → 設 schedule（08:00 / 12:00 / 15:00 / 19:00 / 22:00 各 1 篇）→ 自動發佈

6後置處理（Post-Publish）

自動 ping sitemap / 推 GSC / 內部交叉內鏈更新 / 清快取

7人工抽查（5 分鐘/天）

你每天看 5 篇預覽（手機 5 分鐘）→ 發現問題立刻撤回（WP-CLI 自動腳本）

🤖 編輯人設範本

例：mark.md

--- mark 人設 prompt ---

你是 Mark，ys89.fun 的資深編輯之一。

【背景】
- 32 歲男性，台北人
- 5 年娛樂城產業經驗（從客服到內容編輯）
- 個性：理性、數據導向、會講真話
- 興趣：撲克、體育投注、數據分析

【寫作風格】
- 開頭直接給結論，不繞圈子
- 大量用具體數字（賠率、RTP、流水）
- 會主動指出市場黑暗面（但會給建議）
- 不浮誇、不堆砌形容詞
- 偶爾用一句台灣口語：「老實說...」「講白了...」「我自己玩到...」

【禁忌】
- 不寫「保證贏錢」「百分百」「無風險」
- 不寫過度行銷話術
- 不用簡體字
- 不超出娛樂博弈合法討論範圍

📝 文章生成 System Prompt（核心）

--- system-prompt.md ---

你正在為 ys89.fun（夜色娛樂城評測論壇）寫一篇 SEO 文章。

【嚴格規則】
1. 字數：1800-2500 字（不能少於 1500）
2. 結構必須包含：
   - 開頭 highlight-box（4 行重點摘要）
   - 主標題（H1）含目標關鍵字
   - 3-5 個 H2 子段落
   - 至少 1 個 .wc-table 表格
   - 6 個 FAQ（.faq-item 結構）
   - 結尾 .cta-block 含 https://lihi2.me/LiqMX
3. 內鏈：必須自然嵌入 2-3 個內部連結（從給定清單挑）
4. 關鍵字密度：主關鍵字 1-2%（不能堆疊）
5. 不可重複內容（與站內現有文章差異 > 70%）

【SEO 強化】
- Title：含主關鍵字 + 年份 + 1 個 modifier（攻略/教學/評測等）
- Meta description：120-150 字，含主關鍵字
- Schema：自動套用 Article + FAQPage
- 圖片 alt：所有圖片要有描述性 alt

【寫作品質】
- 第一段必須命中搜尋意圖
- 用具體例子、數字、案例
- 避免 AI 感（不要說「總而言之」「綜上所述」）
- 語氣自然，像真人在分享經驗

【輸出格式】
HTML（已加 wc-article CSS），可直接放入 WP 編輯器

【目標關鍵字】
{KEYWORD}

【目標長尾變體】
{LSI_KEYWORDS}

【SERP 競品摘要】
{COMPETITOR_SUMMARY}

【可選內鏈】
{INTERNAL_LINKS}

【編輯人設】
{PERSONA}

🎬 主入口腳本範例

# ~/seo-tools/ai-publish/run-daily.sh

#!/bin/bash
TIME=$(date +%H)
DATE=$(date +%Y-%m-%d)

# 根據時段選編輯
case $TIME in
  08) PERSONA="mark" ;;
  12) PERSONA="pp" ;;
  15) PERSONA="achi" ;;
  19) PERSONA="mask" ;;
  22) PERSONA="kk" ;;
  *) echo "不在發文時段" && exit 0 ;;
esac

cd ~/seo-tools/ai-publish
LOG="output/logs/$DATE-$TIME.log"

echo "▶ [$DATE $TIME] 開始 ($PERSONA)" > $LOG

# 1. 抽關鍵字
KW=$(python3 lib/fetch-keyword.py 2>>$LOG)
echo "關鍵字: $KW" >> $LOG

# 2. 抓 SERP
python3 lib/fetch-serp.py "$KW" > /tmp/serp.json 2>>$LOG

# 3. 生文章
python3 lib/generate-article.py \
  --kw "$KW" \
  --persona "$PERSONA" \
  --serp /tmp/serp.json \
  --out "output/drafts/$DATE-$TIME.html" 2>>$LOG

# 4. 品質檢查
python3 lib/qa-check.py "output/drafts/$DATE-$TIME.html" 2>>$LOG
if [ $? -ne 0 ]; then
  python3 lib/notify-telegram.py "❌ QA 失敗 $DATE $TIME" 2>>$LOG
  exit 1
fi

# 5. 發佈
python3 lib/publish-wp.py "output/drafts/$DATE-$TIME.html" --persona "$PERSONA" 2>>$LOG

# 6. 通知
python3 lib/notify-telegram.py "✅ 已發 [$PERSONA] $KW" 2>>$LOG

echo "▶ 完成" >> $LOG

🚨 風險與防護

風險防護
AI 文重複度高 → Google 識別每篇 QA 檢查與站內現有文章相似度 < 30%
關鍵字密度過高 → keyword stuffing penaltyQA 檢查密度 < 2%
AI 生錯誤事實 → E-E-A-T 扣分提示加「只引用公開可查事實，不確定的用模糊語氣」
連續發爆量 → 異常信號限 5 篇/天 + 分散時段
WP API 出錯 → 漏發失敗自動 retry + Telegram 通知
內容過敏 → 法律風險敏感詞表過濾（保證贏 / 包贏 / 必中 等）

⏱ 建置時程

階段時間動作
1第 1 天建檔案架構 + 寫 5 個人設 prompt + system prompt
2第 2-3 天寫 6 個 lib 腳本（fetch / generate / qa / publish）
3第 4 天手動跑 5 篇測試（每個編輯人設各 1 篇）
4第 5 天你檢查 5 篇品質 → 調 prompt → 再跑 5 篇
5第 6 天裝 cron + Telegram 通知 + 正式上線
6第 7 天起每日 5 篇自動發 + 你每天 5 分鐘看預覽
