1. 核心觀念：UTM × lihi × GA4 怎麼配合

一句話：UTM 是貼在目的地網址上的「標籤」；lihi 是中轉站；GA4 是收標籤的人。

[廣告/社群連結]    →   [lihi 中轉]    →   [你的網站]   →   GA4 讀標籤
(短網址 / 長 URL)      (lihi 後台統計)     (UTM 跟著到)    (GA4 後台分類)

UTM 標籤

貼在「目的地網址」尾巴，GA4 讀來分類流量來源。

lihi 短網址

中轉站，提供「點擊統計」+「漂亮短連結」。lihi 跳轉時會保留 UTM。

GA4

裝在你的網站上。瀏覽器打開帶 UTM 的網址後，GA4 自動讀取並歸類。

2. 🚨 命名規則鐵則

❌ 禁用清單（違反 = 報表壞掉）

禁用原因正確做法
中文（任何欄位）瀏覽器 URL encode 後變 %E9%98%BF... 報表變天書用英文小寫拼音，如 akki 不是 阿奇
#符號# 在 URL 是「錨點」，會把後面內容切掉標籤用 lihi 內建標籤功能，不要塞 utm
空格URL 空格變 %20 醜爆用底線 _ 連接，如 banner_a
大寫 FacebookGA4 區分大小寫：facebook ≠ Facebook 算 2 個來源一律小寫
medium=adsGA4 不識別，付費流量歸 Unassigned付費廣告統一用 cpc
medium=promotionpromotion 不是 medium，是 campaign 概念medium 用 cpc/post/social...campaign 才寫 promotion
站名當 source（如 wc_site）「自己的站」不算「流量來源」用具體站名 ys89_me + medium=referral

✅ 標準寫法

  • 全部 英文小寫
  • 單字之間用 底線 _ 連接
  • 日期格式：YYYYMM（例：202605）
  • 長度建議 ≤ 20 字元

8. 工作流 SOP

A. 付費廣告（給代操商）

  1. 從 A 區 6 條挑要投的
  2. 不用包 lihi，直接給長 URL（FB/IG/Google 都會擋 shortener）
  3. 同活動換素材 → 改 utm_content（banner_a → banner_b）
  4. 跨檔期 → 改 utm_campaign（wc2026 → wc2026_final）

B. 社群人員（5 人設）

  1. 從 B 區挑對應人設的連結
  2. IG bio = 直接放長 URL（lihi 可能降權）
  3. IG 貼文/限動 = 可以包 lihi（lihi 後台多看點擊數）
  4. 所有人設用同一個 utm_campaign=wc2026 方便加總

C. LINE OA 管理

  1. 圖文選單 6 顆按鈕全部包 lihi（已用）
  2. lihi 目的地填 C 區對應 URL
  3. 除了 LINE 推播訊息也走 medium=chat

驗證 SOP

  1. 新連結發出前，自己用無痕視窗開一次
  2. 進 GA4 即時報表（資源「WC 4 sites」）
  3. 看「使用者依事件來源/媒介」是否出現 source/medium
  4. 看到 = 通過，可以發給代操商/社群
  5. 沒看到 = URL 寫錯，回頭檢查
